# 戏剧情境更新语义底座

## 唯一最小单位

StoryMentor 把“功能上不可再分的情境更新”定义为全项目底层单位。一次有效更新必须使下列至少一个维度产生可说明的 `before → after` 差异：

- W：世界事实
- K：人物知识、信念、怀疑与误解
- G：人物目标与策略
- R：人物关系、权力和情感距离
- D：承诺、规范、债务与许可
- E：观众认知和信息优势

对白、动作、沉默、感知、声音、空间变化和外部事件只是更新载体。字、词、句、段、镜头、场景长度、动作数量和情绪强度都不能独立构成更新。

## 双向编译

固定结构向下编译为大节拍状态契约，再编译为场景状态契约与必要情境更新方案；正文向上提取为外部锚定的更新证据，再确定性归约为场景、大节拍、人物、关系、世界、主题、冲突和全片投影。

作者字段是创作意图，正文投影是实现证据。投影永远是提案，不自动覆盖作者的一句话故事、人物设定、主题、世界、冲突或锁定结构。

## 数据边界

- `DramaticUpdateRecord` 保存更新、W/K/G/R/D/E 差异、因果父节点、置信度、显著性、不可逆性和正文修订指纹。
- `DramaticSourceAnchor` 在 Fountain 之外保存场景 UUID、UTF-16 范围、段落范围、逐字引文和上下文。
- `NarrativeProjectionRecord` 保存各层向上投影、计划—实现缺口和透明节奏指标。
- `SceneStateContract` 保存进入状态、必须变化、不得提前变化、观众离场认知和验证规则。

正文发生变化时，未被作者锁定的旧证据立即标为 stale 并退出归约；分析期间正文变化时，本次结果直接丢弃，避免错挂。

## 节奏

实际节奏只使用确定性公式：

`变化密度 = Σ(有效更新影响值) / 时长（分钟）`

影响值由显著性、不可逆性、置信度、变化维度广度和观众信息不对称透明组合。语言模型只能提出这些可审阅输入，不能直接发明最终节奏分数。作者在大节拍工作台设置的是目标节奏；正文投影显示的是实测节奏。

## 正文编辑器红线

语义层不得进入 Fountain 文本，不得成为新的剧本元素，也不得改写 `FountainTextEditor.Coordinator.textView(_:doCommandBy:)` 的交互契约：

1. 非空段落末尾按 Return，继续使用当前元素的 `nextStyleID`。
2. 新生成的空段落再次按 Return，打开原有文本元素选择器。
3. 自定义元素、段落元素分配和 Final Draft 式元素菜单继续由既有系统管理。

运行 `work/verify_dramatic_semantics.sh` 可检查上述源码边界；Debug 启动还会执行状态归约、节奏与外部锚点的快速不变量测试。
