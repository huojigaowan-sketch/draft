# 心流微挑战引导架构

## 产品约束

默认创作路径服务于完全没有编剧知识的作者。系统必须帮助作者完成剧本，但不得一次生成完整人物设定、完整结构、大纲、完整场景、整集或完整剧本。

每轮只允许一个主要创作问题，并遵循固定闭环：

```text
读取当前项目状态
→ 找到下一项最小未决决定
→ 提出一个微挑战
→ 作者尝试
→ 本地边界检查
→ 可选 AI 单点语义反馈
→ 作者修订或逐级请求支架
→ 确认并写入结构化故事状态
→ 进入下一项微挑战
```

## 五层完成路径

1. **故事核心**：用六个小问题建立吸引点、主人公、外部目标、眼前代价、错误应对方式和一句话故事。
2. **结构推进**：后台采用现有结构模板；每个结构阶段只处理决定、代价、可见证据三个小问题。
3. **场景设计**：每场依次确认地点、视点、即时目标、阻碍、转折、离场结果和下一场压力。
4. **情境更新**：一次只构造一个 before → after 变化，再确认行动、反作用、结果和对应的短小 Fountain 正文。
5. **剧本确认**：逐场检查是否兑现离场结果；一次只修复一个缺口。

完整剧本由作者已经确认的 `SceneMicroBeat.screenplayText` 按因果顺序确定性串联，不通过“一键生成全本”获得。

## 难度与支架

难度不是用户总分，而是当前一步的多维负荷：

- 开放度
- 约束负荷
- 因果跨度
- 状态复杂度
- 执行负荷

系统根据首次通过、失败次数和所用支架动态调整 `targetStretch`。作者也可以手动要求下一步更简单或稍有挑战。

固定支架阶梯：

0. 独立尝试
1. 换一种问法
2. 查看一条规则
3. 查看少量机制
4. 使用句式或半成品
5. AI 只补当前最小步骤

卡住时先降低开放度，不增加 AI 输出长度。

## AI 输出红线

`GuidedFlowCoachEngine` 的结构化输出仅允许：

- 当前回答是否满足契约
- 一句描述性反馈
- 一个下一步提示
- 对作者已决定内容的忠实摘要
- 最后一级支架中的一个短小局部建议

代码还会截断输出长度。AI 不得提前解决后续步骤，也不得自动写入项目；只有作者再次确认后，内容才进入项目状态。

## 数据模型

`GuidedFlowSession` 持久化：

- 当前阶段、对象和小步骤位置
- 当前支架等级与动态步幅
- 作者草稿
- 尝试记录
- 已确认微步骤
- 按挑战 ID 保存的局部答案

它通过 `projectID` 连接现有项目，同时复用：

- `StoryCharacter`
- `StoryDecision` / `StoryChoiceOption`
- `SceneContract` / `SceneChoiceOption`
- `SceneMicroBeat` / `SceneBeatChoiceOption`
- `DramaticStateMutation`
- Fountain 正文与既有版本系统

## 高级工具兼容

默认 `.compiler` 入口切换为 `GuidedFlowWorkspaceView`。原 `NarrativeCompilerWorkbenchView` 保留，并通过“高级结构编译器”入口打开；既有 NSIR、场景工作台、Final Draft 式正文编辑器及格式交互契约不变。
