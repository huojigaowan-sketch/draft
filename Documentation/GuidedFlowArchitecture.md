# 心流微挑战引导架构

## 产品约束

默认创作路径服务于完全没有编剧知识的作者。系统必须帮助作者完成剧本，但不得一次生成完整人物设定、完整结构、大纲、完整场景、整集或完整剧本。

每轮只允许一个主要创作问题，并遵循固定闭环：

```text
读取当前项目状态
→ 找到下一项最小未决决定
→ 提出一个微挑战
→ 作者尝试
→ 本地边界检查
→ 可选 AI 单点语义反馈
→ 作者修订或逐级请求支架
→ 确认并写入结构化故事状态
→ 进入下一项微挑战
```

## 双通道作答：微决定与命题写作

“一次只解决一个问题”不等于“一次只能写一句话”。每个适合展开的微挑战提供两种作答方式：

- **聚焦回答**：用一句到一小段文字确认当前决定，适合快速推进。
- **命题写作**：围绕同一个命题写 300—1200 字，也可以更长；允许使用小说式叙述、动作、对话、回忆和生活细节，不要求剧本格式。

命题写作提交后进入“创作回声”闭环：

```text
作者长文原稿
→ 原样保存为 ProjectArtifact
→ 从原文逐字证据中识别人物、情节、关系、画面、声音与生活细节
→ 只提炼当前微挑战所需的一个 canonical decision
→ 把原文与发现注入后续创作上下文
→ 展示“这篇文字已经创造了什么”
→ 进入下一命题
```

原文永远是作者材料，AI 摘要不能覆盖它。结构化提炼只负责让现有项目模型继续推进。每项 AI 发现必须附带作者原文中的短句作为证据；没有逐字依据的推断不得写入创作回声。

这使新手可以使用熟悉的“命题作文”能力进入创作，同时逐渐理解人物欲望、行动后果、场景转折和剧本状态变化。

## 五层完成路径

1. **故事核心**：用六个小问题建立吸引点、主人公、外部目标、眼前代价、错误应对方式和一句话故事。
2. **结构推进**：后台采用现有结构模板；每个结构阶段只处理决定、代价、可见证据三个小问题。
3. **场景设计**：每场依次确认地点、视点、即时目标、阻碍、转折、离场结果和下一场压力。
4. **情境更新**：一次只构造一个 before → after 变化，再确认行动、反作用、结果和对应的短小 Fountain 正文。
5. **剧本确认**：逐场检查是否兑现离场结果；一次只修复一个缺口。

完整剧本由作者已经确认的 `SceneMicroBeat.screenplayText` 按因果顺序确定性串联，不通过“一键生成全本”获得。

## 难度与支架

难度不是用户总分，而是当前一步的多维负荷：

- 开放度
- 约束负荷
- 因果跨度
- 状态复杂度
- 执行负荷

系统根据首次通过、失败次数和所用支架动态调整 `targetStretch`。作者也可以手动要求下一步更简单或稍有挑战。

固定支架阶梯：

0. 独立尝试
1. 换一种问法
2. 查看一条规则
3. 查看少量机制
4. 使用句式或半成品
5. AI 只补当前最小步骤

卡住时先降低开放度，不增加 AI 输出长度。

## AI 输出红线

`GuidedFlowCoachEngine` 的结构化输出仅允许：

- 当前回答是否满足契约
- 一句描述性反馈
- 一个下一步提示
- 对作者已决定内容的忠实摘要
- 最后一级支架中的一个短小局部建议

代码还会截断输出长度。AI 不得提前解决后续步骤，也不得自动写入项目；只有作者再次确认后，内容才进入项目状态。

## 数据模型

`GuidedFlowSession` 持久化：

- 当前阶段、对象和小步骤位置
- 当前支架等级与动态步幅
- 作者草稿
- 尝试记录
- 已确认微步骤
- 按挑战 ID 保存的局部答案
- 作者命题写作原文、逐字证据和创作回声
- 当前偏好的作答方式

它通过 `projectID` 连接现有项目，同时复用：

- `StoryCharacter`
- `StoryDecision` / `StoryChoiceOption`
- `SceneContract` / `SceneChoiceOption`
- `SceneMicroBeat` / `SceneBeatChoiceOption`
- `DramaticStateMutation`
- Fountain 正文与既有版本系统

## 高级工具兼容

默认 `.compiler` 入口切换为 `GuidedFlowWorkspaceView`。原 `NarrativeCompilerWorkbenchView` 保留，并通过“高级结构编译器”入口打开；既有 NSIR、场景工作台、Final Draft 式正文编辑器及格式交互契约不变。

## 正式剧本终点

引导式心流现在以现有 Final Draft / Fountain 编辑器作为唯一生产表面。结构模板在后台生成硬性剧作义务；每次命题只补当前真实缺口，作者文字被编译进同一份正式剧本。所有结构、场景、情境更新、连续性和格式义务完成并经作者确认后，系统停止出题。完整设计见 [`GuidedFinalDraftWorkflow.md`](GuidedFinalDraftWorkflow.md)。
